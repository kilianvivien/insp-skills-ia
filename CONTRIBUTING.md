# Contribuer au catalogue

Merci de partager vos ressources et vos retours d’expérience ! Ce catalogue est ouvert aux skills
de tous les auteurs, dès lors qu’elles présentent un intérêt pour les élèves de l’INSP et les
pratiques de l’action publique.

## Proposer une skill

Vous avez deux possibilités :

1. [Ouvrir une proposition](https://github.com/kilianvivien/insp-skills-ia/issues/new?template=proposer-une-skill.md) en remplissant le modèle. Aucune connaissance de Git n’est nécessaire.
2. Faire un fork, compléter le catalogue dans `README.md`, puis ouvrir une pull request.

Dans les deux cas, fournissez :

- le nom de la skill et son lien public d’origine ;
- le nom ou pseudonyme de l’auteur et son lien, si disponible ;
- une description courte de la tâche accomplie et de son intérêt pour les élèves ;
- les compétences qu’elle permet de travailler ;
- les modalités d’installation et les agents compatibles, lorsqu’ils sont documentés ;
- la licence, si elle est précisée, et les limites connues ;
- un exemple public ou fictif, ou un lien vers les exemples de l’auteur ;
- ce que vous avez testé, en distinguant votre expérience de la description de l’auteur.

## Ajouter une entrée au README

Utilisez la rubrique la plus adaptée ou créez-en une nouvelle. Voici le format du tableau :

```markdown
| **Nom · `identifiant`** | Tâche accomplie et intérêt concret. | Compétences travaillées. | **[Auteur](URL)** · [Dépôt et installation](URL) · [Exemples](URL) |
```

Conservez les liens vers le dépôt d’origine : il reste la référence pour l’installation, les
versions et la licence. Ne recopiez pas une skill dans ce dépôt pour la référencer.

## Ce qui aide à la relecture

Une proposition utile décrit clairement le besoin, présente une ressource accessible et identifie
son auteur. Évitez les promesses de fiabilité non démontrées. Si vous n’avez pas testé une skill,
dites-le simplement. Signalez les dépendances payantes, les accès demandés ou les limites dont vous
avez connaissance.

Les propositions sont relues par le mainteneur avant leur intégration. Un lien sans licence peut
être proposé en précisant « licence non indiquée » ; le référencement n’accorde aucun droit de
copie ou de modification sur la ressource externe.

## Partager un retour ou corriger le catalogue

Ouvrez une issue ou une pull request pour un lien cassé, une description à améliorer, un exemple
d’usage ou une compétence à ajouter. Indiquez la ressource concernée et la correction proposée.

Utilisez uniquement des cas publics, fictifs ou correctement anonymisés. N’incluez pas de données
personnelles, de documents internes ni d’informations confidentielles dans les contributions.
Respectez les auteurs et formulez des retours précis et constructifs.

Le contenu original que vous proposez à ce dépôt relève de sa licence MIT ; les ressources liées
conservent leur propre licence et leur attribution.
